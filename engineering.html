Strategy first

Last season, our robot was overly complex: it took too many steps to do simple tasks. So this year we started with strategy. After analyzing the game, we decided to score only in the hive. It's faster, it's more efficient, and it earns a ranking point. The flowers don't.

That strategy produced five requirements that every mechanism has to answer to:

  • Simplicity
  • Speed
  • Reliability
  • Accuracy
  • Coding ease

Our design process

  1. 01DefineUnderstand the problem or task.
  2. 02BrainstormCome up with several possible solutions.
  3. 03DesignDraw it, CAD it, and plan concrete steps.
  4. 04PrototypeBuild the physical design.
  5. 05TestRun it and record how it performs.
  6. 06IterateFeed what we learned back into step one.

Current robot · Beta

Born Yesterday: a robot in under 48 hours

Born Yesterday is our current competition robot, and a beta version of our main robot, which is still in the works.

We planned to compete with our main robot, but it needed more time to iterate. On Wednesday, November 11, three days before the Roadrunner – Gilbert Qualifier, we decided to design, build, and program a beta version instead. We finished it in less than 48 hours, and it earned the Inspire Award 3rd Place.

We built it mostly from goBILDA components, which made it fast to iterate and easy to change after assembly. Custom parts are hard to modify once a robot is together, and not everything can be predicted. What we learn from Born Yesterday goes straight into the main robot, which will combine mostly manufactured parts with custom elements.

Pollen path

  1. goBILDA Gecko Wheels pull pollen into the robot.
  2. A belt-driven throughput carries it to the shooter.
  3. The 6,000 RPM shooter launches it into the hive.

The throughput's pulley rides on a bearing, so it shares the shooter's axle but spins independently and never slows the shooter down.

In the works

Our main robot

Born Yesterday is the beta; this is the full version, and it's still in the works. It's built around a dual-turret design that we picked over a variable-width shooter, two fixed shooters, and a single shooter with a compliant wheel.

{% include photo.html name="custom-turret" alt="Turret assembly with a goBILDA motor driving the flywheel shooter." w=1130 h=1209 %}

Dual turret

Steel-weighted flywheels hold speed from the first shot to the last. goBILDA's gear-driven turret turns straight from a gear, with no belts or custom parts. The hood angle comes from a projectile-motion equation, so one launch speed can score from anywhere on the field. The pollen turret is built; the nectar turret is already in CAD.

θ = tan⁻¹[(v² − √(v⁴ − g(gd² + 2hv²))) / gd]

  • 6,000 RPM goBILDA motor
  • Offset Robotics servo on the hood
  • 2 Axon servos guide the turret
  • 4 goBILDA flywheels, 115 g each
  • 332° of rotation
{% include photo.html name="custom-intake" alt="The custom intake assembly with rows of compliant wheels, on a workbench." w=1590 h=1147 %}

Intake

Twelve compliant wheels pull pollen in while beam-break sensors count each piece. At four, the intake shuts off and the shooter spins up. Pollen only moves to the turret when the shooter is at speed and aimed, and the outer bar slides under a flower to pull its pollen out.

  • 6,000 RPM motor, 12 compliant wheels
  • Beam breaks count pollen
  • Holds four, then shuts off automatically
  • Lowers at the start of TeleOp
{% include photo.html name="custom-drive-motors" alt="Two drivetrain motors mounted to an aluminum chassis plate." w=1286 h=824 %}

Drivetrain

Mecanum wheels let the robot drive, strafe, and rotate at once, so it can line up a shot without turning first. Mecanum gives up some traction and pushing power, but our strategy values mobility over defense.

  • Four 435 RPM motors
  • Mecanum wheels
  • goBILDA Pinpoint with odometry pods

Autonomous & control

Code that survived a rebuild

Routines + geometry

Every auto is a routine (what to do), a geometry (where to go), and an identifier. One base auto runs them and mirrors the moves for either alliance, so we can build a new auto for a partner fast.

Localization

A goBILDA Pinpoint combines IMU data with odometry pods to track position and heading all match. Auto hands its position to TeleOp, so nothing needs resetting.

Auto park

The driver holds one button and the robot drives itself to park, even mid-path. In auto, a timeout forces a park before time runs out.

Vision

Vision aims the turret and waits until the hive tips to our side, which makes us more compatible with partners who rely on timed waits.

State machine + triggers

TeleOp runs a finite state machine that switches between intaking and shooting on its own. Global triggers pick the right hive from where the driver lines up, even without vision.

Built to adapt

When we built Born Yesterday in 48 hours, most of the main robot's code carried straight over. Subsystems needed new names and a few values; commands didn't change at all.

Software

Tools we built, and share

ValleyLib

Open source

A command-based library made for FTC and FRC. Each mechanism is a subsystem, each action is a command, and the scheduler keeps two commands from fighting over a motor. Unlike FTCLib, it supports Pedro Pathing. 

PedroAutoDsl.auto(drive, auto -> auto
    .follow(mainPath)
    .waitUntilDriveIdle()
    .action(() -> telemetryBus.put("Status", "Done")));
  • 20 → 4lines for code like this
  • 66automated tests
  • 10releases in two seasons

valleyVis

Path planner

A visual editor for autonomous paths on the BIOBUZZ field, built for ValleyLib and Pedro Pathing. Draw Bézier paths, set headings and speeds, add actions and keep-out zones, then export Java you can paste straight into an auto. It works offline, and share links carry a whole routine.

Open valleyVis

Apex Scout

Scouting app

Built by +3 and Valley X. It works fully offline and moves data between devices with QR codes, so hotspots never interfere with matches. Weighted rankings, official FIRST data, and a pit display that tells teams when to queue. Each team's data stays private to that team.

  • 70+users
  • 10+teams
  • QRsync, no internet
